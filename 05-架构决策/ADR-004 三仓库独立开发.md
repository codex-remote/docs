# ADR-004 独立多仓库开发

## 状态

已修订。应用源码保持五个独立仓库；2026-08-22 明确 Mobile Web Gateway 归属 `mobile-web`。2026-08-23 增加独立 `runtime-distribution`、`homebrew-tap` 和文档仓库，它们属于分发与文档边界，不改变五个应用源码仓库的职责。

## 决策

Codex Remote 采用五个独立源码仓库：

- `iphone-app`：SwiftUI App 与 iPhone 诊断生产端。
- `mobile-web`：与 iPhone 职责一致的用户侧 Web Client，以及独立运行的 Mobile Web Gateway。
- `relay-server`：实时通信服务和 Project/Thread/Turn 协议。
- `mac-agent`：本地 Codex 执行端。
- `admin-platform`：Admin Server、Admin Web、Diagnostics Collector 和诊断/行为 Schema。

五个仓库拥有独立 Git 历史、版本、CI、发布物和依赖清单。父目录不是 Monorepo，也不使用 `go.work`、Git Submodule、符号链接或源码相对导入建立跨仓依赖。

`runtime-distribution` 只组装版本化产物并维护 Runtime CLI/Manifest；`homebrew-tap` 只维护第三方 Formula；`docs` 只维护公开知识库。未来官方 Cask 是 Homebrew 官方仓库中的发布元数据，不改变源码边界。这些仓库与元数据都不得成为跨源码仓库共享实现的渠道。

## 协议归属

`relay-server` 发布实时通信与 Runtime/Auth HTTPS/SSE Schema、Fixtures 和兼容说明。`admin-platform` 发布诊断事件、行为事件、摄入 API 和 Collector 任务 Schema。`iphone-app`、`mobile-web`、`relay-server` 与 `mac-agent` 在各自仓库维护原生模型，并用发布 Fixtures 做契约测试。Gateway 只能代理版本化公共契约，不得导入 `relay-server` 或其他兄弟仓库源码。

## 版本与发布

| 仓库 | 独立版本 | 发布物 |
| --- | --- | --- |
| `iphone-app` | App Version + Build | iOS App、dSYM |
| `mobile-web` | SemVer | Web Assets、Mobile Web Gateway、Runtime Client Fixtures |
| `relay-server` | SemVer | Binary、Docker Image、实时 Protocol Bundle |
| `mac-agent` | SemVer | macOS Binary、launchd Package |
| `admin-platform` | SemVer | Admin Server、Web Assets、Collector、Admin Schema Bundle |

跨仓功能通过兼容矩阵和发布顺序协调，不要求在同一次提交中原子发布。

## 本地工作区

```text
codexremote/
├── iphone-app/.git/
├── mobile-web/.git/           # 已初始化的独立 Git 仓库
├── relay-server/.git/
├── mac-agent/.git/
├── admin-platform/.git/       # 已初始化的独立 Git 仓库
├── runtime-distribution/.git/
├── homebrew-tap/.git/
└── Codex Remote/.git/         # 独立 Obsidian 文档仓库
```

本地并列布局方便联调，但不是任何单仓构建前提。各仓库提交、分支、Tag、CI、Changelog、发布物和回滚均不得依赖父目录或其他仓库的 Git 历史。Mobile Web Gateway 与 Web Assets 同属 `mobile-web` 发布边界，但必须作为可独立监督、健康检查和回滚的进程运行。

Admin Web 重构只能在 `admin-platform` 仓库内提交。需要同步 Relay、Mac Agent 或 iPhone 的诊断契约时，分别在受影响仓库提交，并通过版本化 Schema、Fixtures 和兼容矩阵关联，不能使用一个跨目录提交伪装成原子变更。

## 结果

独立仓库继续提供发布隔离和清晰所有权；代价是跨仓 Schema、Fixtures、兼容矩阵和端到端测试必须作为一等发布产物维护。`mobile-web` 不得并入 Admin Web，也不得通过兄弟目录源码共享绕过公共 Runtime 契约。
