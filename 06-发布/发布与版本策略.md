# 发布与版本策略

> [!important] 当前结论
> Codex Remote 仍处于 Unreleased。局域网可用、本地 Homebrew 安装成功或创建 Git Tag 都不等于公开稳定发布，也不形成兼容性承诺。

## 三条独立发布线

| 发布线 | 包含内容 | 不包含内容 |
| --- | --- | --- |
| macOS Runtime | `runtime-distribution`、`relay-server`、`mac-agent`、`mobile-web` 构建产物与 `homebrew-tap` | iPhone App、Admin Platform |
| iPhone App | `iphone-app` 与其后端兼容矩阵 | Runtime 二进制、Admin |
| Admin/Diagnostics | `admin-platform` | 用户 Runtime 与 iPhone 分发 |

发布线可以独立迭代。跨线兼容通过版本化协议、Fixtures 和兼容矩阵记录，不要求七个仓库同时拥有相同版本或一次性发布。

## Runtime 版本

Homebrew Runtime 使用一个 SemVer 版本号，例如 `0.2.0`。Manifest 必须固定：

- Runtime 版本和发布通道；
- Relay、Mac Agent、Mobile Web 与 Distribution 的精确 commit/tag；
- 数据库 Schema；
- 支持的平台；
- Codex 最低版本和最高已验证版本；
- 每个不可变发布资产的 URL、字节数与 SHA-256。

首版只发布 `darwin-arm64`。不生成 Intel、Universal、Linux 或 Windows 产物，也不通过 Rosetta 隐式支持未验收平台。

## 状态定义

| 状态 | 允许发生 | 兼容性承诺 |
| --- | --- | --- |
| `unreleased` | 本地开发、局域网验收、本地 Formula、草稿文档 | 无 |
| `prerelease` | 已上传的 GitHub pre-release、测试 Tap | 无生产承诺 |
| `released` | 签名、公证、许可证、不可变 Release 和干净机器门禁全部通过 | 从该版本开始 |

当前 [[0.2.0 Homebrew 发布候选]] 为 `unreleased`，阶段是 `local-acceptance-passed`。

## Stable Runtime 门禁

1. 所有 Runtime 输入仓库干净、已推送并拥有不可变 Tag。
2. Apple Silicon 构建可复现，Manifest 与 archive checksum 一致。
3. 每个可执行文件完成 Developer ID 签名，发布资产完成 Apple 公证验证。
4. 公开二进制许可证已确定，完整第三方许可证与 Notice 已审查。
5. GitHub Release URL 不可变，Formula 不包含 `file://`、凭据或私有源码。
6. 干净 Mac 完成安装、Setup、配对、升级、回滚、普通卸载保留数据和显式清除。
7. 已存在 PostgreSQL、Redis/Valkey和默认端口冲突时，不终止或修改外部服务。
8. `codex-remote doctor --json` 通过，真实设备 Run/SSE 通过。

门禁未全部通过时，只能称为本地候选或 pre-release。

## Homebrew 路径

第三方 Tap 首次安装使用：

```bash
brew trust --formula codex-remote/tap/codex-remote
brew install codex-remote/tap/codex-remote
```

其中第一个 `codex-remote` 是 GitHub owner，`tap` 映射仓库 `homebrew-tap`，最后一个 `codex-remote` 映射 `Formula/codex-remote.rb`。

Tap 注册后，本机可以使用短名称升级。干净机器直接运行 `brew install codex-remote`，必须等 Formula 被 Homebrew 官方仓库接收。

## 发布与升级规则

- `brew install` 只安装不可变文件，不创建用户数据或启动服务。
- `codex-remote setup` 才负责 Codex 验证、数据库、凭据、端口、LaunchAgent 与健康检查。
- `brew upgrade`、`brew reinstall`、失败 Setup 和普通卸载必须保留用户数据。
- 破坏性数据库迁移前必须备份，并有升级、回滚或恢复证据。
- 已发布的 archive、manifest、Tag 和 Formula commit 不得改写；修复产生新版本。
- 发布后按 SemVer：不兼容变更升 Major，兼容能力升 Minor，兼容修复升 Patch。

## 版本更新流程

1. 冻结并测试 Runtime 输入 commit。
2. 生成 Manifest，构建确定性 archive，完成签名、公证和许可证检查。
3. 创建组件 Tag 与 Runtime Tag，上传 archive、manifest、checksum 和 Release Notes。
4. 用准确 URL/SHA 更新 `homebrew-tap/Formula/codex-remote.rb`。
5. 在干净 Mac 执行完整安装/升级/回滚/真机门禁。
6. 发布 Tap；稳定后再准备 Homebrew 官方 Formula 提交。

完整的机器可执行流程由 `release-codexremote-runtime` skill 和 `runtime-distribution` 脚本维护，本文只定义发布政策。
