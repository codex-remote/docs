# 0.2.0-beta.1 Homebrew 公开 Beta

> [!warning] beta.1 已被阻塞缺陷取代
> Runtime `0.2.0-beta.1` 已于 2026-08-24 发布并通过远程 Homebrew 安装，但默认 `~/Library/Application Support/CodexRemote` 路径中的空格导致 Valkey 配置解析失败。该版本不得继续推荐，修复版本为 `0.2.0-beta.2`。

## beta.1 事故与 beta.2 修复

- 症状：Setup 报 `Valkey: port 63800 did not become ready`。
- 根因：Valkey `dir` 指令直接拼接默认路径，`Application Support` 被拆成多个参数。
- 排除：端口未占用，Valkey arm64 二进制和动态库正常，问题与签名、公证无关。
- 修复：路径和密码统一引用并转义，拒绝 CR/LF/NUL；服务启动失败时按逆序卸载本次新加载的 LaunchAgent。
- 回归：覆盖空格、引号、反斜杠、控制字符、真实 Valkey 启动和逆序回滚。
- 版本策略：保持 `beta.1` Tag 与资产不可变，以新 Tag 发布 `0.2.0-beta.2`。

## 已通过验收

- 通过本地 Formula 执行 `brew install codex-remote` 的安装验收。这不代表干净机器已能全局解析该短命令。
- 与现有 PostgreSQL 14、Redis 8.0.2 并存，没有 unlink 或停止用户服务。
- 使用 Homebrew PostgreSQL 17 的独立数据目录。
- 使用 Runtime 内置 Valkey 9.1.1 的独立数据目录和端口。
- 默认端口被占用时自动选择并持久化 Gateway `18777`、Run Server `18778`、Auth `18779`、PostgreSQL `54330`、Valkey `63800`。
- 五个用户 LaunchAgent 全部加载。
- `codex-remote doctor --json` 返回 `ok: true`。
- Mac Agent 连接 Relay；全新 Codex 尚无 Project 时仍可健康启动。
- 二维码生成成功且文件权限为 `0600`。
- iPhone Safari 单标签扫码、刷新恢复、真实 Run/SSE、退出和控制面撤销通过。
- 临时验收 Runtime 已清除，原开发栈保持健康。

## 安装职责

`brew install` 只安装不可变文件和 `postgresql@17`，不发现 Codex、不初始化数据库、不生成凭据、不分配端口、不注册 LaunchAgent，也不启动服务。

`codex-remote setup` 负责 Codex 发现与真实 App Server 握手、隔离 PostgreSQL/Valkey、Keychain 凭据、动态端口、迁移、LaunchAgent、健康检查和局域网地址。已有 PostgreSQL、Redis 或 Valkey 不会被修改。

## 对外安装命令

第三方 Tap 发布后：

```bash
brew trust --formula codex-remote/tap/codex-remote
brew install codex-remote/tap/codex-remote
codex-remote setup --workspace-root ~/work
codex-remote pair
```

干净机器直接运行 `brew install codex-remote` 是后续的 Homebrew 官方 Cask 里程碑。闭源 Runtime 不符合 `homebrew/core` Formula 的开源许可要求。官方 Cask 接收前，不能省略第三方 Tap 的首次信任与安装路径。

## 已知限制

- 仅支持 Apple Silicon。
- 局域网 Safari 双标签 Refresh Token 轮换存在竞态，当前按单标签使用。
- 公网 TLS、稳定域名、限流、Cursor 过期恢复、多实例和长期压力尚未放行。
- Beta 明确未签名、未公证，不构成生产兼容与支持承诺；Stable 仍必须完成 Developer ID 签名和 Apple 公证。
