# 第一阶段开发计划

> [!important] 计划边界
> 当前三端 MVP 已经存在。本计划只交付独立 Admin/Diagnostics 本地闭环，不把用户生产认证、业务 Run 持久化、多 Mac 路由或完整 SLS 生产上线混入同一阶段。可靠 Runtime 已另由 [[可靠多端运行时分阶段开发计划]] 独立规划。

## 1. 阶段目标

建立第四个独立 `admin-platform` 项目，让开发者从一个本地管理页面查看 Relay、Mac Agent 和 iPhone 的结构化诊断证据，可靠持久化事件和附件，并通过受控 CoreDevice 任务主动获取真机诊断文件。

> [!success] 完成定义
> Relay 和 Mac Agent 继续正常工作时，Admin/Collector 可以独立停止、恢复并补齐日志；一次 iPhone OOM 事故能够通过本地事件、MetricKit、系统证据和关联 ID 形成可供人和 AI 复查的事故包。

> [!info] 2026-08-13 实施状态
> PostgreSQL Admin Server、独立 Collector、确认式 checkpoint/spool、Relay/Mac JSONL、Simulator App Data Container、事件查询、服务状态、附件导入、租约式 CoreDevice 任务，以及版本化 Incident 固定证据快照已经实现并完成本机 E2E。RBAC/审计、真机 OOM 证据链、iPhone 生产自动上传与 SLS 仍按后续里程碑实施。

> [!success] Admin Web 已完成
> D 方案工作台、统一 `/api/v1` 和旧页面/API 硬删除已经完成。下一实施项是 A3/A4：真机 iPhone 持久上传状态机、CoreDevice 受控拉取和真实 OOM/MetricKit/sysdiagnose 证据闭环。

## 2. 完整阶段交付范围

- [x] `admin-platform` 独立 Git 仓库、本地构建入口、版本文档和基础 CI；独立远端仍待配置。
- [x] Admin Server + Admin Web 模块化单体。
- [x] Diagnostics Collector 独立进程与 launchd 开发配置。
- [x] PostgreSQL 14+、本地附件目录、版本化迁移和运行容量上限。
- [x] Relay/Mac Agent JSONL 发现、轮转、游标、批量确认和幂等采集基础能力。
- [ ] iPhone JSONL/MetricKit 自动上传状态机和 CoreDevice App Data Container 受控拉取；当前已完成 Simulator 自动采集、诊断包导入与 CoreDevice 设备发现/任务租约。
- [x] Events、Services、Devices、Captures、Artifacts、Incidents 页面。
- [ ] 人类 JSON/NDJSON 导出和 AI Incident Snapshot；当前已完成 Incident `v1` JSON Snapshot，NDJSON 与面向 AI 的精简视图仍待实现。
- [ ] RBAC 最小角色和敏感操作审计。
- [x] 技术事件隐私 allowlist、历史字段清理和摄入回归测试。
- [ ] 故障注入、轮转、重启、重复提交、OOM 证据链和真机验证；当前已覆盖 Collector 重试、轮转、部分行、超长行、重复提交与 Simulator 闭环。

## 3. 本阶段不做

- 把 Admin/Diagnostics 接口加入 Relay。
- 完整用户中心、计费、团队、多租户和运营后台。
- 生产 SLS Project/Logstore、告警和长期保留上线。
- iPhone 生产 STS 服务和 App Store 数据披露。
- Relay 可靠业务 Task、离线任务和多 Mac 调度。
- 允许浏览器执行任意 Shell、任意路径或任意 CoreDevice 参数。

## 5. 实施顺序

### A0：Schema 与工程边界

- 确认 `admin-platform` 独立 Git 根目录，冻结当前已验证实现的首个基线 commit；清理或迁移未验证原型，不把草稿当基线。
- 定义技术事件、行为事件、审计事件和附件 Manifest 的独立 Schema。
- 定义摄入批次确认、`event_id` 幂等、Collector 任务与回报协议。
- 固化时间、时区、关联 ID、脱敏、截断、采样和 Schema 版本规则。
- 建立跨仓 Fixtures 和兼容矩阵。

### A1：Admin Server 与 Web

- 实现配置、迁移、健康检查、优雅停机和资源限制。
- 本地使用 PostgreSQL 14+，附件保存到独立目录并记录 SHA-256。
- 使用独立 migration role 和最小权限 runtime role；超级账号只用于一次性 bootstrap。
- 第一阶段不引入 Redis，任务领取和幂等写入使用 PostgreSQL 事务与约束。
- 实现 Admin/Diagnostics API 分区、RBAC 和审计中间件。
- 建立服务总览、事件列表、详情、数据源和时间范围组件。
- 查询必须分页、有最大扫描范围，并标识截断与采样。

### A2：Relay/Mac Agent 文件采集

- 将现有 `slog` JSON 对齐统一字段，不记录 Prompt、响应、Diff 和凭据。
- 使用滚动 JSONL 和容量上限，日志压力不阻塞业务。
- Collector 实现文件标识、偏移、头部指纹、轮转和截断识别。
- 组批提交后只按服务端确认推进游标；重复批次由 `event_id` 去重。
- 对 Collector 自身 CPU、内存、延迟、积压和丢弃建立监控。

### A3：iPhone 诊断

- 保持 Unified Logging、现有 bounded JSONL 和 MetricKit Schema。
- 引入持久密封段和上传队列，开发/线上共用同一状态机。
- 验证启动、前台、后台、断网、恢复、队列上限和失败退避。
- Collector 使用公开 `devicectl device copy from` 拉取已密封诊断目录。
- 拉取 Bundle ID、目录和任务类型均来自 allowlist；使用 `--json-output`。
- 系统 crash logs 与 sysdiagnose 使用独立强确认和审计。

### A4：事故与证据

- 支持按 Session、Trace、Turn、用户引用、设备引用和版本关联事件。
- Incident 固定查询窗口、事件快照、附件 Manifest、Schema 和结论。
- 人类导出与 AI Snapshot 使用相同证据，包含数据源、时区和脱敏说明。
- 通过一次真机资源异常或可控模拟验证证据链。

### A5：SLS 兼容

- 建立测试 Logstore、索引、保留和最小权限查询配置。
- 使用 LoongCollector 采集服务端相同 JSONL。
- 使用 iOS SDK 测试 Producer 缓存和 STS 临时凭据，不接入长期 AccessKey。
- Admin 查询适配器显示 Local/SLS 数据源，不做隐式长期双写。

## 6. 测试策略

| 层级 | 重点 |
| --- | --- |
| Schema | Go/Swift/TypeScript 解码、未知字段、版本与隐私 allowlist |
| Store | PostgreSQL 迁移、事务、幂等、分页、保留和备份恢复 |
| Collector | 轮转、截断、重启、部分行、批量确认、退避与容量 |
| Admin API | RBAC、审计、查询上限、附件哈希和流式传输 |
| iPhone | 离线队列、后台、重启、网络恢复、MetricKit 和内存边界 |
| CoreDevice | 设备选择、Bundle ID、路径 allowlist、超时、取消和真机拉取 |
| E2E | 三端事件进入页面、关联事故、导出后由人和 AI 读取 |
| 故障注入 | Admin/Collector/SLS 停止、磁盘满、重复提交、慢消费者 |

## 7. 验收矩阵

- [x] Admin/Collector 停止不影响 Relay 连接或 Mac Agent Turn。
- [x] Admin 运行时账号不是 PostgreSQL 超级用户，迁移与运行权限分离。
- [x] Redis 未成为第一阶段启动依赖。
- [ ] Relay/Mac Agent 轮转和重启后事件不静默丢失。
- [x] 同一批次重复提交不会产生重复事件。
- [x] Collector 的磁盘和内存积压都有硬上限与状态显示。
- [x] iPhone 日志从生成开始先落盘，App 重启后仍可由开发 Collector 补采。
- [ ] 开发环境 CoreDevice 只能拉取注册 App 的诊断目录。
- [ ] OOM/Jetsam 不依赖终止回调，能关联 MetricKit 与系统证据。
- [x] 摄入层使用集中字段 allowlist，Prompt、响应、Token、授权头、完整路径和永久设备 ID 不进入新事件；历史非 allowlist 字段已迁移清理。
- [ ] 用户、行为、技术日志、审计和附件使用不同权限与保留策略。
- [x] Incident Snapshot `codexremote.incident.snapshot.v1` 可被人和机器读取，并说明数据源、UTC、窗口、截断、来源计数和隐私策略。
- [ ] SLS 测试环境可解析同一 JSON Schema。

## 8. 当前验证基线

- Admin `go test ./...`、`go vet ./...` 和 `make build` 通过。
- PostgreSQL 运行账号为非超级用户 `codexremote_admin_app`，数据库时区为 UTC。
- Relay、Mac Agent、iPhone Simulator JSONL 经独立 Collector 入库，checkpoint 仅在服务端确认后推进，当前 spool 为 0；2026-08-13 复验中启动 App 后 iPhone 事件在 6 秒内从 186 增至 189。
- 2026-08-13 再验证已使用非 Mock Simulator App 连接 `simulator` Relay，实际切换连接后 `app_connected=true`；App JSONL 与 Relay JSONL checkpoint 前移、Collector spool 为 0，Admin/Collector 重启后 PostgreSQL 事件仍可查询。
- iPhone 单元测试 9/9 通过；UI 测试 24 项中 21 项通过。
- 3 个 UI 用例单独复跑仍失败：连接开关未进入断开态、中断按钮未出现、项目加载提示未出现。它们属于当前 iPhone 工作区的未关闭验证项，不能以构建成功替代修复与交互复验。
- Incident 受控 E2E 已验证创建、事务快照、Admin 重启后读取、JSON 下载、1024px 页面和测试数据清理；真实 OOM 的 MetricKit/sysdiagnose 关联仍未验证。

## 9. 阶段出口

完成验收后冻结 Admin Schema `v1.0-rc1` 和本地容量基线，再单独立项生产用户认证、完整用户/行为后台、SLS 正式环境与移动端隐私发布。可靠 Runtime 已由 [[ADR-007 PostgreSQL 权威运行时与 Redis 实时加速]] 接受并按独立计划实施，不能顺带放入 Admin Diagnostics。
