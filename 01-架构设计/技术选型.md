# 技术选型

## 选型总览

| 层 | 技术 | 决策 |
| --- | --- | --- |
| Relay Server | Go、`net/http`、`coder/websocket` | 保持低依赖的实时通信中枢 |
| Mac Agent | Go、Codex App Server、launchd | 本地执行与出站连接 |
| iPhone App | SwiftUI、Swift Concurrency、URLSession | 原生生命周期、网络与无障碍行为 |
| Mobile Web | TypeScript、React、Vite | 用户侧 Runtime HTTPS/SSE 客户端 |
| Mobile Web Gateway | Go `net/http`、`httputil.ReverseProxy` | 独立 module/进程，静态资源、版本化路由 allowlist 与 SSE 透传 |
| iPhone 系统诊断 | OSLog、MetricKit、CoreDevice | 使用公开 Apple API 和 Xcode 工具 |
| Admin Server | Go 模块化单体 | 提供 Admin API、Diagnostics API、权限和任务编排 |
| Admin Web | TypeScript + React | 适合扩展用户、行为、设备、诊断和审计工作台 |
| Diagnostics Collector | Go 独立进程、launchd | 增量文件采集和受控 CoreDevice 操作 |
| Admin 主数据库 | PostgreSQL 14+ | 开发阶段即统一用户、权限、诊断、事故和审计模型 |
| Collector 本地状态 | 原子 checkpoint + 有界 spool 文件 | Admin 不可用时保存游标和待确认批次，不直接连接数据库 |
| 线上日志与行为 | 阿里云 SLS | 大规模检索、统计、告警和保留策略 |
| 诊断附件 | 本地目录 / S3 兼容对象存储 | 保存大文件，数据库只存索引、哈希和权限信息 |
| 指标与 Trace | OpenTelemetry，投递 SLS | 统一 Logs、Metrics、Traces 的关联字段 |
| 服务端日志 | Go `slog` JSON Handler | 一行一条标准 JSON，便于 Collector 和 LoongCollector 采集 |
| Schema | JSON Schema + 版本化 Fixtures | 跨 Go、Swift、Web 和 AI 工具验证 |

> [!note] 实现状态
> Relay/Run Server、Mac Agent、Mobile Web Runtime、Go Gateway、Runtime Auth、iPhone 诊断基线、PostgreSQL Admin Platform 和独立 Collector 已经存在。Gateway 使用 Go `net/http`/`httputil.ReverseProxy`；SLS、RBAC/审计、用户管理和公网硬化仍是后续目标。

## 数据库边界

### PostgreSQL

第一阶段即使用 PostgreSQL 14+ 作为 Admin Platform 的唯一权威数据库，保存管理员身份与角色、未来用户资料、服务实例、诊断事件索引、采集任务、事故、附件索引和管理审计。开发、测试、生产使用独立数据库和最小权限账号，通过相同迁移保持 Schema 一致。

本地已验证 PostgreSQL 14.20 在 `127.0.0.1:5432` 可用。运行时不使用 PostgreSQL 超级账号；超级账号只用于一次性创建数据库和最小权限角色。连接串只通过环境变量或本机密钥配置注入，不写入仓库、文档示例或前端资源。

PostgreSQL 不承担无限保留线上海量日志、保存 sysdiagnose 大文件正文或替代 SLS 检索告警的职责。

### Collector 本地状态

Collector 仍不直接连接 PostgreSQL。它使用本地原子 checkpoint 记录文件身份与已确认偏移，使用有界 spool 文件保存待重试批次。Admin API 确认稳定 `event_id` 后才推进 checkpoint；崩溃恢复允许重复提交，由 PostgreSQL 唯一约束幂等去重。

### MySQL

当前不同时支持 MySQL。PostgreSQL 是第一阶段确定的开发与生产迁移目标，避免维护两套 DDL、事务和查询语义。未来只有明确基础设施约束时才重新评估。

### Redis

Admin/Diagnostics 第一阶段不引入 Redis。单 Admin Server、单机 Collector 和 PostgreSQL 任务表已经足够；Redis 不得成为 Admin 任务、事故或审计的唯一事实来源。

独立 Runtime 已按 [[ADR-007 PostgreSQL 权威运行时与 Redis 实时加速]] 实现 Redis Result Stream、presence 和 Session 通知主链；Stream 容量、终态清理、故障转移和多实例仍属生产硬化。该决定不改变 Admin Platform 首阶段不引入 Redis 的边界。

### SLS

SLS 是线上日志和用户行为的数据面。Admin Server 通过受控查询适配器读取 SLS，页面不持有云端密钥，也不直接拼接无限制查询。

## 日志采集技术

Relay 和 Mac Agent 使用异步 JSONL 文件日志：业务进程只负责有界写盘，Collector 或 LoongCollector 负责增量读取、轮转识别、缓存、重试和投递。禁止每条日志同步调用 Admin API。

iPhone 采用本地滚动 JSONL 与持久上传队列：

- 开发和线上共用批量、退避、采样和容量限制；
- 开发环境额外允许 CoreDevice 从 App Data Container 拉取密封日志段；
- 线上通过 SLS iOS SDK 和 STS 临时凭证上传；
- MetricKit、系统崩溃日志和 sysdiagnose 作为附件，不展开为普通日志行。

## API 与部署边界

- 局域网浏览器的当前入口是 Mobile Web Gateway `:18774`；页面与 `/v1/runtime/*` 共用单一 Origin。
- Run Server `mobileweb` profile 当前只监听 `127.0.0.1:18775`；未来公网连接器仍只指向 Gateway。
- Gateway 仅代理明确 allowlist 的 Runtime/Auth 路径，不代理 Agent WSS、Auth Control、Admin、数据库或调试端点。
- Relay API 与 Diagnostics API 使用不同服务和权限模型。
- Admin Server 同时提供 Admin Web 静态资源和版本化管理 API。
- 日志摄入 API、管理查询 API、设备操作 API 在代码与路由上分区。
- Collector 不连接数据库，只调用摄入和任务回报 API。
- CoreDevice 命令必须由 Collector 的固定参数模型生成，禁止接收任意命令文本。
- 本地模式默认监听 `127.0.0.1`；真机摄入使用独立监听配置和短期 Token。

## 不选择的方案

| 方案 | 不选择的原因 |
| --- | --- |
| 把 Diagnostics API 加进 Relay | 放大实时通信故障域，混合权限和扩容模型 |
| Collector 直接写 PostgreSQL | 强耦合数据库 Schema，绕过摄入权限、幂等确认和审计边界 |
| Admin 第一阶段引入 Redis | Admin 当前没有跨实例缓存或协调需求，只会增加部署和故障面；不适用于独立 Runtime 决策 |
| 每条业务日志实时 HTTP 上报 | 增加业务延迟、网络、电量和 OOM 风险 |
| 所有线上日志写 PostgreSQL/MySQL | 检索、保留和容量成本不适合日志数据面 |
| iPhone 只依赖终止回调上传 | Jetsam/OOM 强杀时不保证回调 |
| App 内保存长期 SLS AccessKey | 移动端凭据可被提取，必须使用 STS 最小权限临时凭证 |
| 网页提交任意 Shell 命令 | 无法建立设备操作安全边界和审计 |

## 版本与兼容

事件 Schema、行为 Schema、摄入 API、Collector 任务协议分别版本化。添加可选字段保持向后兼容；字段改义或删除必须提升主版本。日志字段变化需要同时更新生产端、采集配置、索引、页面查询、测试和文档。

Admin 尚处于 Unreleased。[[ADR-006 Admin Web 一次性重构]] 已完成 Web/Admin API 原子切换且不保留无版本旧 API；正式发布后的兼容规则再由发布基线确定。
